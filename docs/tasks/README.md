# Task briefs

Self-contained work items for parallel agents (Claude subagents, Codex,
or a human). Each brief says what to find or build, where the evidence
is, which files it may touch, and how to know it is done. The coordinator
(the main Claude session) reviews and merges branches into `main`.

## Protocol

0. **Use the board** (`docs/BOARD.md`): join, claim your area and files
   before editing, report status, read your inbox. The board is where the
   head assigns briefs and where agents settle overlaps.
1. **Take only a brief assigned to you** (an `assign` message from `head`
   on the board). To take an `open` one, ask `head` first.
2. **Work in your own worktree and branch** so builds and edits never
   collide:
   ```
   git -C E:/ddda-rs worktree add E:/ddda-rs-wt/<id> -b task/<id> main
   ```
   Build and test only what you touch (`cargo test -p <crate>`); building
   `ddview` (Bevy) in every worktree costs gigabytes.
3. **Stay inside the brief's scope.** New crates under `crates/` are
   picked up by the workspace glob; do not edit the root `Cargo.toml`
   unless the brief says so. Do not edit `docs/MILESTONES.md` or
   `docs/ROADMAP.md`: report in your brief's **Results** section instead,
   and the coordinator updates them on merge.
4. **Commit on your branch** as
   `git -c user.name=janne -c user.email=marcelovjunior55@gmail.com commit`,
   with no AI co-author or "generated by" trailer. Never push. Never merge
   into `main` and never rebase `main`.
5. **Finish** by filling in the brief's Results: what was found (with
   addresses, file paths, counts), what was built and tested, what is
   still unknown, and the next step. Then set Status to `review`.
6. All rules in `AGENTS.md` apply: derive values from data, exe or
   recordings, never invent; label guesses; never commit game files,
   `E:\ddda-re` contents or decompiler exports; the install is read-only.

## Tools available to every agent

- **Game data:** `E:\SteamLibrary\steamapps\common\DDDA\nativePC`
  (read-only). In Rust: `ddvfs::Vfs::open(..)`, then `vfs.read(path,
  mtarc::type_hash("rClassName"))`. List resources by type with
  `vfs.paths_of_type(..)`; `mtarc::RESOURCE_CLASSES` names the 144 types.
- **CLI:** `cargo run --release -p ddtool -- <cmd>` (see `ddtool` usage):
  `xfs-get <nativePC> <path>` dumps any XFS resource (most `param\` files).
- **Exe:** Ghidra MCP over HTTP at `http://127.0.0.1:8089` (read-only use):
  `/decompile_function?address=0x00aca5d0`, `/disassemble_function?address=`,
  `/get_xrefs_to?address=`, `/get_function_by_address?address=`. Class
  names, vtables and virtual functions: `E:\ddda-re\notes\dti-labels.csv`
  (address, kind, namespace, name, source) and `dti-registry.json`.
  If the server is down, start it with `E:\ddda-re\tools\start-ghidra-mcp.ps1`.
- **Exe bytes for scripts:** `E:\ddda-re\bin\DDDA.exe.unpacked.exe`, helper
  `research/dti/peimg.py`; Python with capstone at
  `E:\ddda-re\tools\pyenv\Scripts\python.exe` (run with `-I`).
- **Reference specs (MIT):** `E:\ddda-re\refsrc` (Riftstone, Albam). Read
  them; cite them; do not copy code without the license note in
  `third_party/`.
- **Live game:** not available unless the maintainer is present. Do not
  attach debuggers or write to the game's memory.
