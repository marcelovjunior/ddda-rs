## Problem

`lift.py gen` now emits about 25,600 functions: 106 MB of Rust in 65
modules under `crates/ddnative/src/generated/`, and
`cargo test -p ddnative --test lifted` takes about 16 minutes to build
from scratch on 16 cores. It is also committed to git on every regeneration.

Most of the bulk is repeated text: the `*cpu = Cpu { eax, ecx, ... }` /
`Cpu { ... } = std::mem::take(cpu)` sequences around every call and return,
the `{ let a = ...; let c = ...; let r = ...; fl = Flags::new(...); }`
blocks, `wrapping_add(0x...)` address arithmetic, and so on.

## Task

Make the generated code much smaller and faster to compile **without
changing what it does** (same reads, same writes, same results; the
vectors judge):

1. Measure first: total generated bytes, the build time of the lifted test
   (from a clean `ddnative` build and after touching one generated module),
   and where rustc spends its time if you can tell (`-Z time-passes` needs
   nightly; `cargo build --timings` works on stable).
2. Shrink the emitted text. Ideas, not requirements: `macro_rules!`
   defined inside each function after the `let` bindings (they can name
   the locals: macro hygiene resolves local identifiers at the definition
   site) for save/load and the flag-setting blocks; shorter helper calls in
   `x86`/`mem` (e.g. an address helper); dropping flag computations that no
   later instruction can read before they are overwritten (only with a
   proof from the control flow, and keep `Flags` exact where they are
   read).
3. Compile-time settings that do not affect correctness: `codegen-units`,
   `opt-level` for this crate in the test/dev profile, splitting modules
   differently, `#[inline(never)]` or `#[cold]` where it helps. Measure each.
4. Report before/after for size and both build times.
