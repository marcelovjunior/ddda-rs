# L54: entry points reached through indirect calls

- **Owner:** claude-6

## Task (from the head)

The emulator fallback (L51) ran four entries on the boot's route to the
title that the inventory lacks: 0x01325580 and 0x01325830 (after
FUN_01325560), 0x013271E0 (after FUN_01326EF0) and 0x012F4E74 (after
FUN_012F4E6A). They are reached through indirect calls. Admit them by a
general rule: an indirect-call target the original reaches at run time,
recorded as runtime evidence, plus the boundary checks. Then lift and
record them, and look statically for more entries of the same kind
(callback tables, function pointers stored by verified code).

Data: `native-L54`, a copy of the frozen `native-L50`.

## Results

(claude-6; branch `task/L54`)

**What the four are.**
- **0x01325580, 0x01325830, 0x013271E0** are slots of libvorbis-style
  export tables in `.rdata`: the floor table at 0x014701E0 (7 slots) and
  the residue table at 0x01470210 (a NULL first slot, then 6). Verified
  code calls them through the table array at 0x01467D38 (claude-2, head
  #9850).
- **0x012F4E74** is the `fmod` body after the `_CIfmod` stub, named in
  the `_CI` descriptor at 0x01455D30. The `_CI` core's dispatcher jumps
  to it.

**Rule 1, runtime evidence** (`discover_functions.py --runtime FILE`).
- **The file:** private JSON of targets the original reached at run time,
  with the indirect call and its function: `native-L54/runtime_entries.json`,
  from claude-2's ddplay emulator run.
- **The calls:**
  - 0x01325580 from `call eax` at 0x01311DC2 in 0x01311CD0;
  - 0x01325830 from `call edx` at 0x01312D34 in 0x01312A80;
  - 0x013271E0 from `call ecx` at 0x013238BA in 0x01323460;
  - 0x012F4E74 from the frame of `call 0x01300497` at 0x013046AB in
    0x01304690 (the dispatcher's jump).
- **The checks:** the same as an address-taken entry. The target is
  executable, at a function boundary, inside no known function, and
  passes `code_entry`.

**Rule 2, callback tables** (`callback_tables`, static).
- **The table:** a run of aligned dwords in non-executable data, each
  either 0 (an unused callback) or an executable address. It must hold at
  least two code pointers, at least one of them a known entry.
- **Its base:** the base, a leading NULL or the first code pointer, must
  be referenced somewhere in the image (a table is used through its
  base).
- **Its members:** every other member must be at a function boundary,
  inside no known function, and not text-like. Three printable bytes and
  a NUL, such as "shp\0" after a vtable, is no evidence of a pointer. If
  any member fails, nothing in the run is admitted.
- **Writable tables:** they count too, since their initial pointers are
  code the image names; the evidence marks them `writable`.
- **Before the base and text checks,** the rule also admitted string
  tails that follow vtables (0x006D6574 "tem", 0x00706873 "shp").

**Found statically: 29 new entries, all lifted and recorded.**
- **The two vorbis tables (6):** the head's three plus 0x013273F0,
  0x01327650 and 0x01327680. With the three already known, these are the
  nine table targets claude-2 listed.
- **Other read-only tables (10):**
  - members of other function tables: 0x01322540 and 0x013239F0,
    0x01324EA0 (tables at 0x0146FD60 and 0x0146FD80);
  - scalar deleting destructors and similar slots: 0x00898090,
    0x00ABAC00, 0x00E76790, 0x01080630, 0x0130A600 (vtable runs without
    RTTI anchors);
  - 0x0112BC00, in a record array at 0x01441CF0;
  - 0x00DCCD30, already lifted, which only gains its inventory entry.
- **Writable tables (13):** 12 slots of the dispatch table at 0x0163537C
  (0x011ADBA0 to 0x011AE320), and 0x00659030 in the table at 0x01875754.
- **By runtime evidence only:** 0x012F4E74. Its `_CI` descriptor is
  referenced at its base, 16 bytes before the pointer run.
- **Function pointers stored by verified code** were already covered by
  discovery's `address_taken` rule (immediates in lifted bodies); nothing
  new came from it.
